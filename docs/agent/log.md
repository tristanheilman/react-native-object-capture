# Agent coordination log

One line per run. Newest first. Read this **and** every file in
[`plans/`](plans/) before starting, so runs don't repeat or collide with each
other. Add a line when you finish — including when you finish by deciding not to
do something, since "we looked and chose not to" is the finding most likely to
be re-derived from scratch otherwise.

## Before you pick something up

1. **Check for an open PR against the ticket.** This repo takes outside
   contributions. If a PR exists, the work is claimed — say so and pick
   something else. Do not produce a competing branch from the ticket text.
2. **Check the plan's Sequencing section.** Some plans are blocked on other work
   landing, usually because they touch a file an open PR already modifies.
3. **Check `Codeable vs. owner`.** Some steps end in a decision that is the
   maintainer's, not yours. Bring the measurement back rather than deciding.

Repo-wide constraints — iOS-only by design, New Architecture, release-please,
conventional commits, what needs a device — are in
[`../../AGENTS.md`](../../AGENTS.md). Read it first.

- **2026-10-06** — **Multi-pass capture fixed end to end: [#45](https://github.com/tristanheilman/react-native-object-capture/pull/45).** Started from uncommitted device-debugging work on `fix/scan-pass-state-guard`; verified every fix on an iPhone 16 Pro Max (iOS 26) with temporary `isPaused`/`state` logging streamed via `xcrun devicectl device process launch --console` (Release build, no Metro needed). **Findings worth keeping, several undocumented by Apple:** (1) `beginNewScanPass()` on a paused session flips `isPaused` false then true again within ms, and a `resume()` in that window is lost — capture freezes for good. Apple's docs call starting a pass while paused valid and their GuidedCapture sample does it, but it resumes only after a sheet animation. Fix: `beginNewScan` resumes first and waits for `isPaused` to settle. (2) `beginNewScanPassAfterFlip()` **traps** if called right after `resume()`, but works paused — so the flip path must *not* pre-resume — applying the same fix to both paths crashes the app on flip. (3) `isPaused` updates asynchronously in both directions; never gate on a read taken right after `pause()`/`resume()`/a new pass. (4) `resume()` on a running session is harmless — the original WIP's `if isPaused` guard was based on a misread and was dropped. (5) `ObjectCapturePointCloudView` does not pause the session while `ObjectCaptureView` stays mounted beneath it. (6) After a pass completes, there is no "back to the same pass" state — only new pass, flip, or finish — so the example's pass-screen Cancel was removed.
